# Infin8X — project rules

Studio site for **Infin8X (Infinite eXperience)**. Concept: the logo is a prism. White light (an idea) enters at the crossing (the X),
travels the white lobe, returns to the X and disperses into the spectrum lobe. Every section reuses that story.
Art direction: deep navy, teal-cyan particle filaments with depth of field, real 3D glass.

## Conventions
- **Copy lives in `src/content/*.ts`.** Components never hard-code copy. Unknown facts → `[PLACEHOLDER: …]`, unconfirmed seeds → `[CONFIRM]`, and list them in `docs/TODO-CONTENT.md`. Never invent clients, stats or testimonials.
- **Logo geometry is generated.** Do not hand-edit `src/brand/logoGeometry.ts`. Path space is the PNG's own 1904×610. Check alignment at `/?debug`.
- Path parameter `u ∈ [0,1)`: `0` = crossing heading into the right lobe, `SPLIT` = crossing again, `[SPLIT,1)` = left lobe. Use `pointAt`, `colorAt`, `U_LEFT`, `U_RIGHT` from `src/brand/pathMath.ts`.
- **Hero:** `HeroIntro.tsx` owns the GSAP timeline; `hero/artworkBackdrop.ts` renders the logo artwork + `auroraCurtain.ts` backdrop in
  **one WebGL context** and only draws the timeline's state. Change timing in the timeline, looks in the renderers.
- **Files:** raw source material lives in `source-assets/` (`fonts/` original font files incl. uploads, `logo/` the source renders used by
  `scripts/extract-logo.py`); only subset woff2s ship from `public/fonts`. Screenshots go to `shots/` (ignored).
- **Device tiers:** GPU → full 3D. Software WebGL / ≤2 cores / ≤2 GB / data-saver (`isLowEnd()`) → lite hero (wordmark + flat 8, CSS
  background), no live canvases, no reveals. Phones/tablets report ≤4 GB even with a strong GPU, so ≤4 cores / ≤4 GB / touch / <900px
  is only `isConstrained()`: everything animates, the site background on its compressed budget (`quality: 'low'`: fewer particles,
  3 logos, 0.8 pixel ratio, 30 fps; no backdrop blur on the veil for `.touch`). This is what keeps Lighthouse ≥ 90 (Lighthouse runs without a GPU). Exception: the hero intro uses
  `canPlayIntro()` (any real GPU, no Data Saver), so phones also play it regardless of reported CPU/RAM. Devices reporting ≤2 cores
  or ≤2 GB use the lite shader, no MSAA, pixel ratio ≤1 and an 800k-pixel cap. Reduced motion skips the intro timeline;
  `.lowend` hero rules are scoped to `.hero--lite`.
- Hero backdrop: `hero/auroraCurtain.ts` — full-screen shader: a warp fan of long-exposure light fibres sweeping from both edges into the ∞'s crossing (cool blue on the white lobe side, hot red/magenta on the spectrum side), energy flowing inwards in log space, starburst behind the X, nebula + stars, glossy floor with the logo's live mirrored reflection (`artworkBackdrop.ts` renders the logo flipped about the contact line into `aurora.reflection` first), film grade. Intro story (timeline in `HeroIntro.tsx`, states in `artworkBackdrop.ts`): `aurora` energy enters random fibres as comet heads that draw them edge→core → `rush` energy races into the core → `flash` absorption → `trace` light draws the ribbon in path order (crossing → white lobe → crossing → spectrum lobe; analytic path coordinate in `colourFlow.ts`) → `calm` fibres are absorbed into the core one by one at random (outer end retracts with a glowing tail; ~1 in 7 survive softly). Never pop fibres on/off with a step — retract or draw them. Spectrum-side fibres use `brand/flowPalette.json`.
- Section headers (`Chapter.tsx`): no numbering anywhere; the section name is set large and faded above the h2 (filled gradient, never `-webkit-text-stroke`, which shows the variable font's inner contours). Home nav hides its wordmark while the hero is in view. Never add a drop-shadow/halo to it (it reads as a box shadow over the bright background).
- **Type** (tokens in `styles/tokens.css`, woff2 subsets in `public/fonts`, sources in `source-assets/fonts/`): `--font-display` **Baserona** (wide geometric caps: headings, buttons, nav, card titles), `--font-body` **Unique** (paragraphs, UI, forms), `--font-label` / `--font-figure` **Biscora** (condensed caps: small tracked labels; big project names, stats, step numbers), `--font-ghost` **Esthoria 72 Italic** (the faded section names only; demo cut subset to A–Z/a–z/space because its period is a watermark and it has no digits), `--font-accent` **Epstonik** `ss03` only for the "Infinite Experience" reading, `--font-script` **Lightning Crashes** (the handwritten curve face, `.script-copy`: section titles of About/Services/Process/Contact, the Work lead, About principle labels, the hero services line, the footer base line — kept on request, never remove it), `--font-read` **Manrope** (variable, `@fontsource-variable/manrope`) for section descriptions, Services card titles, skill tags and the Process details. Services card points, the Services link, the Work project tags and the Process ribbon's deliverables use `--font-name` (Bricolage; condensed caps there were rejected). Biscora's `&` reads as a G, so `--font-label`/`--font-figure` take the ampersand alone from Unique ('Biscora Amp', unicode-range). Never restyle the logo, the Infin8X wordmark (Ariovex + Turbo Driver), "Infinite Experience", or `.hero__wm` (Unbounded). Unusable uploads: Starstone, Bellina (watermarked glyphs), Cravelo (no digits/punctuation), Dusty Grunge (texture off-brand). Esthoria/Cravelo/Starstone/Bellina are personal-use demos: license before commercial launch.
- Section header (`Chapter.tsx`): Esthoria italic name, the h2 tucked into its lower edge; `--fs-h2` is compact so title and lead sit on one line from tablet up. Reveals: no blur-in — titles rise word by word out of a mask, leads rise softly, the section name wipes on left→right.
- No green anywhere outside the logo artwork: the spectrum's fourth stop is `--s-magenta` (#D94CFF), used by Work, the Apps card and Process step 05.
- Nav (desktop ≥1000px): wordmark alone on the left, one glass pill on the right — icon-only section buttons (dark-glass name tag on hover/focus), the current section a capsule in its accent colour **sized to its measured label** (`--w`/`--cap`/`--capmax` from `Nav.tsx`, label opens behind a feathered mask edge), round send (contact) and menu buttons. The row is as wide as the widest capsule and buttons are right-aligned in it by **transform**; the pill's glass is `.nav__pill::before`, trimmed to the visible buttons with `clip-path` (`--trim`), so the pill always fits its content and scrolling causes no layout shift; keep it that way. Behind the **wordmark** `.nav::before` is a compact slanted navy-glass streak from the LEFT screen edge (≈1.7× the wordmark's height, ends just past it; outer veil + core band; hidden while the hero shows the logo, slides in with the wordmark; blur-free on `.lowend`). Phone hero (<768px): fills the screen (`min-height: max(520px, 100svh)`), its block centred under the nav, and the wordmark is centred on the screen (the desktop crossing offset is turned off there). Below 1000px there is no glass bar: the wordmark (19px) stands alone over its streak, and 360–999px shows the section icons in one compact glass pill (buttons scale with `--b`, the current section is an accent puck that glides by transform from `--k`, round white contact button, no menu). Under 360px only, a separate round glass menu button opens the sheet.
- Intro plays at 2× its authored timings (`INTRO_SPEED` in `HeroIntro.tsx`); change speed there, not per tween.
- Services scenes rest; they play on card hover/focus and all together for 5 s every 15 s while in view (`data-play` on `.svc-grid`).
- Buttons (`.btn`): Manrope 700, plain words + a small direction icon. Nav icons are their own `nav-*` set in `Icon.tsx`, each drawn for its section (two overlapping rings, service tiles + diamond, pen nib, 3:1 split screen, prism splitting light, speech bubble), not stock glyphs.
- Screen edges: fixed soft dark fades at the top and bottom (`body::before/::after`, below the nav).
- Removed on request: the Process prism diagram and its legend box, the six-step line, then the clock dial, the About "Building since 2021" milestone timeline, the footer's section links (they live in the top nav), the footer's Start a project / LinkedIn / Back to top buttons and the full stop after "Every pixel matters", the visible "Selected work." heading under Work (kept for screen readers via `Chapter hideTitle`), the About "From the first sketch to launch." line, the Work "Have a project in mind? Start a conversation" row, the shortened repeat intro (the full intro plays every visit), the background glass-strike/crack effect, the SN15 and Amuse projects.
- Process (`Process.tsx`): an original Infin8X fountain pen drawn in SVG (navy lacquer, gold trim, logo medallion on the clip, name engraved on the barrel ring; no third-party brand). The six steps are ONE satin ribbon wound round it as a helix whose radius/lean/spacing/width drift so no two turns match (pitch 96); colours blend step to step; each step's name/deliverable sit on the curve via `textPath` under the cloth's shading, with a small dart-and-chevron number badge. Details show only on hover/focus/tap: a medallion (step icon) pinned on the band's end and a banner in the band's colour unrolling from it (inset panel + arrow tip with the step number), alternating sides on ≥1000px (the card fills the free side column, up to 400px), docked under the last band below that. Bands take turns catching the light while nothing is open. No ink writing under the nib and no “Every pixel matters” text wall behind the pen (both removed on request). Never use SVG `filter`s or hide SVG children for the entrance: the entrance runs on the HTML stage (clip-path wipe); observe `.pen` (not the clipped stage) and read the LAST IntersectionObserver entry (entries arrive batched on slow frames).
- Services cards each have their own action label (`cta` per service in `content/sections.ts`), not one repeated phrase.
- Services: four short cards in one row (≥1100px, ~365px tall, scene 96px; 2×2 from 640px): icon+name, outcome, animated `ServiceScene`, points in two columns, link. Phones (360–639px): small rounded SQUARE cards two per row (icon + arrow button on top, name, the scene scaled whole with `zoom`); outcome and points are hidden there until a tap: the grid has 6 tracks (squares span 3); the tapped card takes the whole top row (`order: -1`) with outcome, points and its scene scaled UP (`zoom` > 1, scenes are drawn for ~270px cards, so never stretch the box instead), and the other three become one row of mini squares (span 2) right under it. Every card glides from its old spot (FLIP in `Services.tsx`, 550 ms: translate+scale for moving/shrinking cards, a clip reveal for the growing one; tap again or another card to switch). Under 360px the cards stay full (all copy, no expanding). Never drop the scenes. Skills: one block per category (small tag heading + its chips), packed like a watch-face grid: `flex: var(--n) 1 calc(var(--n) * 5.4rem)` so the blocks fill every row.
- Skills numbers (no colour dots/bars — removed on request; number left, tracked label + a factual note from the data beside it; Bricolage numbers, Manrope labels) sit INSIDE the preview banner: a glass aside on its right ≥900px (the spotlight keeps the left), a strip along its foot below. The header is title + lead only.
- Skills is its own route `/skills` (`pages/SkillsPage.tsx`, lazy), reached only from the nav (`chapterHref` in `content/site.ts`); it is not on home.
- Nav glass (bar, desktop pill, phone pill) is real glass: a light tint with a saturated/brightened backdrop so the colours behind show through, and the scene's clock light reflected on its top where it stands (`--scene-light`, `--sun-x`, `--sun-glow` published by `lightField.ts`; static defaults on lite/low-end). The section accent belongs only to the current capsule/puck, never tints the glass. Signature: `.nav__pill::after` is a prismatic rim (1px conic spectrum, masked to the edge) lit only where the scene light strikes (`--sun-pos`), trimmed with the pill on desktop.
- Scroll: no native scrollbar; `.nav__progress` is a 2px hairline at the very top edge of the screen (white → spectrum, revealed by clip-path from `--p`, no glow; shown once scrolled past the hero).
- Work: Kaaya — café & restaurant website (kaayacafe.pages.dev); Dolly — agency portfolio website (dollydstudio.pages.dev); UC8 — digital marketing agency website (uc8.vercel.app); KA — creative portfolio website (kethan.pages.dev). All four use screenshots of the live sites in `public/work/`. Keep the descriptions consistent in `projects.ts` and `projectPresentation.ts`.
- Work layout (≥960px): narrow name index left (.44fr); right a 16:10 glass screen split **2×2** (`.reel__split` grid). Projects take turns expanding every 2 seconds: the selected row and column become `3fr 1fr`, with a .55s grid transition. Hover/focus holds the selected project (the Pause/Play button was removed on request). The name index stretches to the screen's height (rows share it; the stage is not sticky). Under both, one details row on the same columns (subgrid): discipline eyebrow (Manrope caps, a short accent line, no dot) + project name (`--font-figure`) under the index, summary/tags/link under the screen. No empty column beside or under the list. Suspend rotation offscreen, in hidden tabs and for reduced motion. Reduced motion uses equal quarters until manual selection. Narrow screens keep the staggered two-column collage (`.work-gallery`), varied frame shapes and fixed angles, upright names and disciplines, one full-tile project link per item. Keep the reading order stable and the links separate; never reshuffle randomly on render.
- Home sections mount one per idle slice inside `.home__sections`, which holds `min-height: 300vh` until all are mounted: keeps the footer from jumping into view (CLS was 0.22 on phones). Faded effects must bake alpha into colours, not `opacity`: the reveal sets `opacity: 1`.
- Site background after the hero: `three/lightField.ts` via `components/PrismFlow.tsx` (fixed canvas) + `.prismflow-veil` (dark-tinted frosted glass between it and the copy, strongest in the reading column). One light drives everything and follows the visitor's **clock** (`clockLight()`: sun left→right by day, warm low / white high, dim blue moon at night; `?hour=20` previews). Scene: clustered blue/gold particle clouds with soft bokeh, and `three/floatingLogos.ts` — 3D-extruded Simple Icons marks (+ a generic `</>`) that materialise, float near the focus plane and disintegrate into a swirling glitter/wisp/ray particle burst. Post: depth of field (per-pixel rotated disk — no ghost copies) + quarter-res gaussian bloom; overlay: small prismatic streak flares, a fine anamorphic flare, beam, leak, scrim. Counts are deliberately minimal for CPU/GPU; low-end gets the CSS fallback. Rejected before: glass shards (removed on request), ray fans, the mist flow, hard discs, text halos/box shadows behind copy.
- Glass strikes (logos flying into the veil and cracking it, `glassImpact.ts`) were built and then removed on request: logos drift and dissolve in place.
- Intro prismatic shards: `shards()` in `hero/auroraCurtain.ts` — slow spectral slivers on the energy clock (`uFlow`) streaking into the crossing during `aurora`/`rush`, each absorbed at its own random distance; they stop completely as `trace` starts (requested: no rays after the absorption).
- Intro sky follows the visitor's clock like the site background: `uSun` (same rule as `clockLight`, re-read every 20 s, `?hour=` previews) moves the pink light at the top (rises left, high at noon, sets right; dim violet at night) and the warm side of the nebula. Drifting blue/gold bokeh dust (`dust()`, one disc per grid cell, constant cost) sits in the intro background.
- Performance: the backdrop shader is shaded at 60% of the drawing buffer (50% on the lite shader) into a target and blended up (`aurora.draw`); the logo stays full resolution. Keep new backdrop effects soft/cheap; never render the backdrop at full res again.
- Navigation into a home section from another route (e.g. "All projects" → `/#projects`, shared `/#contact`): `TransitionLink` records the section, home waits until it has mounted, finishes the intro and jumps there (App.tsx).
- Section names: fully opaque gradient in the section's own colour; it drifts slowly on its own (14 s) and scroll carries it further (`--ghost-drift` + `--ghost-scroll`, registered). The pointer lights the letters under it (a radial layer clipped to the text, only while the pointer is over the text's line boxes) with a faint soft spill (`::before`). The box is padded on all sides (offset by margins) so the italic is never cut; the reveal clip is generous for the same reason. Section padding `clamp(36px, 4vw, 56px)` (≈112px between sections on desktop, 72px on phones); keep spacing tight, no empty bands.
- Skills: category filters are tiny one-line capsules (no icons; the row scrolls with an edge fade only when it overflows); the preview has no hint line; background icons drift like dust on random clocks and only change while invisible; the centre icon hands over with a goo ("symbiote") morph.
- Work tiles show the site version that fits the tile (desktop / `coverTablet` / `coverMobile` captures in `public/work/`; very wide strips show the whole desktop shot fitted over a blurred copy). The desktop shot is the base and never fades; the others fade in over it (no flicker).
- Footer (`Footer.tsx`, `chrome.css`): phones = centred stack (closing line on ONE line sized by `vw`, brand lockup, © · tagline on one line); ≥768px = side by side (closing line | lockup, then © | tagline). Lockup: the wordmark is sized (24.6px, X padding dropped) so its letters span exactly the width of "Infinite Experience" on one centre line.
- About principles: one horizontal ray on every screen, Idea and Detail above it, Craft centred below (grid placement only; DOM order stays Idea → Craft → Detail); sentences hold 2 lines from 360px up.
- Cursor is the system cursor (custom cursor removed on request).
- Motion: expo-out entrances, `--ease-light` for light travel, 0.4–1.2 s, stagger 40–80 ms, never bouncy. Everything must have a `prefers-reduced-motion` path (final lit state, no travel).
- Glass: use `.glass` + `.glass--e1..3`. Max 3 blurred layers in view on mobile.
- Small accent-coloured text uses `color-mix(in srgb, <accent> 62%, #fff)` to keep 4.5:1 contrast.
- Sections drive the progress beam and the background's spotlight/cool-light colour through `data-chapter` + `--section-accent` (the old `data-accent` selector matched nothing).
- Keep Lighthouse mobile ≥ 90 in all four categories (last run: 92 / 100 / 100 / 100).

- Contact form rules live in `src/lib/contactRules.ts`, shared by the form and `functions/api/contact.ts` (never fork them): name letters only 2–80, real email, details 20–2000 with real words (no link/repeat spam), budget optional (letters/numbers/currency). Send is `aria-disabled` until valid (pressing shows the errors); honeypot + 3 s time trap (bots see "sent", nothing is sent); one message per minute per browser (localStorage). Error copy in `contact.errors`.
- Background bloom: 4-tap box bright pass at quarter res + the gaussian twice (contiguous taps) and interleaved-gradient noise in the DOF; the old sparse taps made square, pixelated, flickering glows.

## Docker
`docker compose up --build` (or `docker build -t infin8x . && docker run -p 8080:80 infin8x`) builds with Node 22 and serves `dist` from
nginx (`docker/nginx.conf`: SPA fallback, long cache for hashed assets). The Cloudflare contact function does not run there; the
form falls back to email / LinkedIn.

## Deploy (Cloudflare Workers, current project)
The Cloudflare project is a **Worker** (deploy command `npx wrangler deploy`). `wrangler.jsonc` serves `dist/` as static assets with
SPA fallback, and `worker/index.ts` routes `/api/contact` to the handler in `functions/api/contact.ts`. Without `wrangler.jsonc`,
Wrangler tries to configure Vite automatically and fails on Vite 5. Set `RESEND_API_KEY` / `CONTACT_TO` / `CONTACT_FROM` under the
Worker's Settings → Variables and Secrets. Check locally with `npx wrangler deploy --dry-run`.

## Deploy (Cloudflare Pages, alternative)
Build command `npm run build`, output `dist`. Functions in `functions/` deploy automatically.
Set env vars `RESEND_API_KEY`, `CONTACT_TO`, `CONTACT_FROM` for the contact form. Without them the form falls back to `mailto:`.
Update `siteUrl` in `src/content/site.ts`, `index.html` meta, `public/robots.txt` and `public/sitemap.xml` once the real domain is known.
